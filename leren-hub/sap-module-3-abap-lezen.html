01

Wat is ABAP en waar leeft het?

⏱ 25 min

ABAP is de taal waarin SAP zélf geschreven is

ABAP (Advanced Business Application Programming) is SAP's eigen programmeertaal. Het bijzondere: niet alleen het maatwerk van jouw klant is in ABAP geschreven, maar een enorm deel van de SAP-standaard zelf ook. Als je door standaard-SAP-code kijkt, lees je dus dezelfde taal als waarin een ontwikkelaar bij jouw klant een uitbreiding bouwt.

Voor jou als BA betekent dat: de code die "doet wat het systeem doet" is leesbaar. Je kunt zelf een stap zetten in de vraag "waarom gebeurt dit hier?" — zonder meteen een developer nodig te hebben.

Het doel van deze module

Je leert code lezen en herkennen, niet schrijven. Denk aan het verschil tussen een taal kunnen volgen op vakantie versus hem vloeiend spreken. Voor analyse, impactvragen en goede overdracht is lezen precies genoeg.

Drie soorten "brokken" code die je tegenkomt

SoortWat het isHerken je aan
Report (programma)Een programma dat je start; leest vaak data en toont of verwerkt het. Het klassieke "los draaibare" ding.Begint doorgaans met REPORT; heeft vaak een selectiescherm.
Function moduleEen herbruikbaar "blokje functionaliteit" met een naam, dat je vanuit andere code aanroept met invoer en uitvoer.Wordt aangeroepen via CALL FUNCTION '...'.
Class / methodeDe moderne, objectgeoriënteerde manier: functionaliteit gebundeld in classes met methoden. In nieuwere SAP steeds dominanter.Woorden als CLASS, METHOD, aanroep met ->.

Je hoeft het onderscheid niet diep te beheersen. Wél helpt het om te wéten: "dit is een op zichzelf staand programma" versus "dit is een blokje dat ergens anders wordt aangeroepen".

Waar kijk je ernaar? (verifieer per systeem)

  • SE38 — de klassieke ABAP Editor, vooral voor reports. Hier open en lees je een programma.
  • SE80 — de bredere "Object Navigator": reports, function modules, classes, alles in één boomstructuur. Veel mensen werken hier het liefst.
  • In moderne omgevingen gebeurt ontwikkeling vaak in ADT / Eclipse (ABAP Development Tools) — maar de code die je leest is dezelfde.
Niet uit je hoofd leren

Transactiecodes zoals SE38/SE80 en de precieze menu's verschillen per systeem en release, en een BA heeft niet altijd leesrechten. Het punt is niet de code onthouden, maar wéten dát code te openen en te lezen valt — en aan wie je dat vraagt.

Controlevragen
1Waarom is het handig dat ook de SAP-standaard in ABAP geschreven is?Toon antwoord
Omdat de code die het systeemgedrag bepaalt daardoor leesbaar is in dezelfde taal als het maatwerk. Je kunt dus zelf in standaardgedrag én in uitbreidingen kijken om te begrijpen "waarom gebeurt dit" — zonder meteen een ontwikkelaar nodig te hebben.
2Wat is het verschil tussen een report en een function module?Toon antwoord
Een report is een programma dat je zelf start (vaak met een selectiescherm). Een function module is een herbruikbaar blokje dat door andere code wordt aangeroepen met invoer en uitvoer. Je herkent een aanroep aan CALL FUNCTION.
3Moet je SE38/SE80 uit je hoofd kennen?Toon antwoord
Nee. Het zijn de plekken waar je code bekijkt, maar exacte codes en menu's verschillen per systeem/release, en een BA heeft niet altijd toegang. Belangrijker is te weten dát code leesbaar is en aan wie je toegang of uitleg vraagt.
02

Basissyntax leren lezen

⏱ 30 min

Je hoeft de grammatica niet te beheersen — alleen een handvol patronen te herkennen. Met deze vier regels lees je al verrassend veel ABAP.

Regel 1 — een statement eindigt op een punt

Elke opdracht in ABAP eindigt met een punt (.). Dat is je belangrijkste leeshulp: de punt markeert "hier is deze instructie klaar". Eén instructie mag gerust over meerdere regels lopen; pas de punt sluit hem af.

DATA lv_naam TYPE string.
lv_naam = 'Polis 4711'.

Twee statements, elk netjes afgesloten met een punt.

Regel 2 — DATA maakt een variabele

Het woord DATA betekent: "maak een doosje om iets in te bewaren". Daarna komt de naam, en meestal TYPE + het soort inhoud (tekst, getal, datum…).

DATA lv_bedrag TYPE p.        " een getal (bedrag)
DATA lv_klant  TYPE string.   " een stuk tekst

Je hoeft de types niet te kennen. Je hoeft alleen te zien: "hier wordt een variabele met deze naam geïntroduceerd." Namen als lv_ (local variable) zijn een veelgebruikte gewoonte, geen wet.

Regel 3 — toekenning met =

Een enkel isgelijkteken (=) stopt de rechterkant ín de linkerkant. "Neem deze waarde en bewaar hem in dit doosje."

lv_bedrag = 1000.
lv_klant  = 'De Vries'.

Regel 4 — commentaar telt niet mee

Tekst die door de programmeur voor mensen is bedoeld (uitleg), niet voor de computer:

  • Een sterretje * aan het begin van een regel: die hele regel is commentaar.
  • Een dubbele quote " ergens op een regel: alles ná die quote tot het regeleinde is commentaar.
* Deze hele regel is uitleg voor de lezer
lv_bedrag = 1000.   " en dit stukje ook
Handig voor jou

Commentaar is vaak jóuw beste vriend: goede ABAP-code legt in commentaar uit waarom iets gebeurt. Lees die regels eerst — ze zijn in gewone taal geschreven en geven vaak direct de businessreden.

Regel 5 — hoofdletters maken niet uit

ABAP is case-ongevoelig voor sleutelwoorden en namen: DATA, data en Data zijn hetzelfde. Conventioneel schrijft men sleutelwoorden vaak in HOOFDLETTERS, maar dat is stijl, geen betekenis. Let op: tekst tussen aanhalingstekens (echte gegevenswaarden) is wél hoofdlettergevoelig.

Controlevragen
1Hoe zie je waar één ABAP-instructie eindigt?Toon antwoord
Aan de punt (.). Elke instructie sluit af met een punt; hij mag over meerdere regels lopen, maar pas de punt maakt hem "af". De punt is je belangrijkste leeshulp.
2Wat doet de regel DATA lv_klant TYPE string.?Toon antwoord
Die introduceert een variabele met de naam lv_klant die tekst (string) kan bevatten — een leeg "doosje" om straks een klantnaam in te bewaren. Er wordt hier nog geen waarde ingezet.
3Wat betekent een " midden op een regel?Toon antwoord
Alles ná die dubbele quote tot het einde van de regel is commentaar: uitleg voor de lezer die de computer negeert. Een * helemaal vooraan maakt de hele regel commentaar.
03

Internal tables & work areas

⏱ 30 min

Een tabel in het geheugen

Een internal table is een tabel die tijdelijk in het werkgeheugen leeft terwijl het programma draait. Zie het als een spreadsheet dat de code even vasthoudt: meerdere rijen, elk met dezelfde kolommen. Het is niet de databasetabel op schijf (die zag je in Module 2) — het is een kopie of werkverzameling waar de code mee rekent.

" een tabel-in-geheugen die polisregels vasthoudt
DATA lt_polissen TYPE TABLE OF zpolis.

Je hoeft de exacte syntax niet te kunnen schrijven. Herken alleen: TABLE OF betekent "een verzameling rijen van dit soort". Namen die met lt_ beginnen (local table) zijn een veelgebruikte hint dat het om zo'n interne tabel gaat.

De work area: één rij tegelijk

Om met de rijen te werken, gebruikt code vaak een work area (of "structure"): een plek voor precies één rij. Denk aan een leesplankje waar je telkens één regel op legt om te bekijken of te bewerken.

DATA ls_polis LIKE LINE OF lt_polissen.   " ruimte voor één rij

Namen met ls_ (local structure) of wa_ (work area) wijzen daar vaak op. Het onderscheid dat telt: lt_ = de héle tabel (veel rijen), ls_/wa_ = één losse rij.

Het idee van "loop over de rijen"

Het meest voorkomende patroon: de code loopt rij voor rij door de tabel en doet per rij iets. Je leest dat als "voor elke rij…":

LOOP AT lt_polissen INTO ls_polis.
   " ls_polis bevat nu telkens de 'huidige' rij
   "  ... hier gebeurt iets met die ene polis ...
ENDLOOP.

Lees dit gerust hardop: "loop door lt_polissen, stop elke rij in ls_polis, en herhaal tot ze op zijn." Binnen de lus verwijst ls_polis steeds naar de rij waar de code nu mee bezig is.

Waarom dit telt voor de BA

Als je in code een LOOP ... ENDLOOP ziet, weet je: "hier wordt per rij iets gedaan — mogelijk voor elke polis, elke order, elke klant." Dat is precies waar businessregels per record worden toegepast. Herken je de lus, dan herken je waar de logica "per stuk" zit.

Controlevragen
1Wat is het verschil tussen een internal table en de databasetabel uit Module 2?Toon antwoord
De databasetabel staat permanent op schijf (de bron). Een internal table leeft tijdelijk in het werkgeheugen terwijl het programma draait — meestal een kopie of werkverzameling van rijen waar de code mee rekent. Weg zodra het programma stopt.
2Wat is het verschil tussen lt_polissen en ls_polis?Toon antwoord
lt_polissen is de hele tabel (veel rijen); ls_polis is een work area voor één rij. De lt_/ls_-namen zijn een gangbare (niet verplichte) conventie om dat verschil te tonen.
3Wat vertelt een LOOP AT ... ENDLOOP je als lezer?Toon antwoord
Dat de code rij voor rij door een tabel gaat en per rij iets doet — "voor elke polis/order/klant…". Het is dé plek waar logica "per record" wordt toegepast, dus waardevol om te herkennen bij impactanalyse.
04

SELECT: data uit tabellen

⏱ 30 min

Dit is misschien wel het waardevolste dat je uit deze module meeneemt. Met SELECT haalt code data uit een databasetabel — dezelfde tabellen die je in Module 2 leerde plaatsen. Als je een SELECT kunt lezen, kun je vaak zelf beantwoorden: "waar komt deze data vandaan?"

De drie woorden die je zoekt

SELECT vbeln erdat netwr     " WELKE kolommen
  FROM vbak                    " uit WELKE tabel
  INTO TABLE lt_orders
  WHERE vkorg = '1000'.        " met WELKE filter

Lees het als een zin: "Haal de kolommen vbeln, erdat en netwr uit tabel vbak, voor de rijen waar vkorg gelijk is aan 1000, en zet het resultaat in mijn interne tabel lt_orders."

WoordVraag die het beantwoordtWat jij eruit haalt
SELECT ...Wélke kolommen (velden)?Welke gegevens worden opgehaald (of * = alle).
FROM ...Uit wélke tabel?De brontabel — koppel terug aan Module 2 (bv. vbak = verkooporder-kop).
WHERE ...Met wélke voorwaarde/filter?Welke selectie/afbakening wordt gemaakt (bv. één verkooporganisatie).
Terugkoppeling naar Module 2

De naam achter FROM is een tabelnaam uit het datamodel. Zie je FROM vbak, dan weet je: deze data komt uit de verkooporder-koptabel. Zo verbindt Module 3 (de code) zich rechtstreeks met Module 2 (waar de data staat). Tabelnamen verschillen per systeem — verifieer altijd.

Twee smaken die je zult zien

  • SELECT ... INTO TABLE lt_... — haalt meerdere rijen in één keer op en zet ze in een interne tabel.
  • SELECT SINGLE ... INTO ls_... — haalt precies één rij op (bv. bij een unieke sleutel). Het woordje SINGLE is je hint: "verwacht één record".
SELECT SINGLE name1
  FROM kna1
  INTO ls_klantnaam
  WHERE kunnr = lv_klant.   " één klant op klantnummer
Grens van je leesbegrip

Je hoeft geen JOINs, subqueries of performance te doorgronden. Kunnen zien welke tabel en welke filter in het spel zijn, is voor analyse al enorm waardevol. Zodra het echt ingewikkeld wordt (meerdere gekoppelde tabellen, geneste logica): noteer je vraag en leg hem bij de ontwikkelaar.

Controlevragen
1Wat doet deze code: SELECT * FROM vbak INTO TABLE lt_orders WHERE vkorg = '1000'.?Toon antwoord
Hij haalt alle kolommen (*) op uit tabel vbak (verkooporder-kop), maar alleen de rijen waar vkorg = 1000 (verkooporganisatie 1000), en zet die rijen in de interne tabel lt_orders. Kortom: "geef me alle verkooporders van organisatie 1000".
2Op welk woord let je om te weten wáár de data vandaan komt?Toon antwoord
Op FROM — daarachter staat de brontabel. Dat koppelt direct terug aan het datamodel uit Module 2. Onthoud wel: tabelnamen verschillen per systeem/release, dus verifieer.
3Wat is het verschil tussen SELECT ... INTO TABLE en SELECT SINGLE?Toon antwoord
SELECT ... INTO TABLE haalt meerdere rijen op in een interne tabel. SELECT SINGLE haalt precies één rij op (meestal via een unieke sleutel). Het woord SINGLE is je hint dat er één record wordt verwacht.
05

Controlstructuren lezen

⏱ 30 min

Controlstructuren bepalen de volgorde en keuzes in de logica: "als dit, doe dat", "herhaal voor elke rij", "kies het juiste geval". Dit is waar businessregels zichtbaar worden. Je hoeft ze niet te schrijven — alleen de vertakkingen te kunnen volgen.

IF / ELSE — een keuze

IF lv_bedrag > 10000.
   lv_status = 'Handmatige controle'.
ELSE.
   lv_status = 'Automatisch akkoord'.
ENDIF.

Lees: "Als het bedrag groter is dan 10.000, dan handmatige controle; anders automatisch akkoord." Dat is een businessregel die je zó aan een proceseigenaar kunt voorleggen. De blokken worden netjes afgesloten met ENDIF.

Een uitgebreidere keten gebruikt ELSEIF:

IF lv_land = 'NL'.
   lv_tarief = 21.
ELSEIF lv_land = 'DE'.
   lv_tarief = 19.
ELSE.
   lv_tarief = 0.
ENDIF.

CASE — een keuze uit veel gevallen

Als er veel mogelijke waarden zijn, is CASE overzichtelijker dan een lange IF-keten. Lees WHEN als "in het geval van…":

CASE lv_type.
   WHEN 'A'. lv_tekst = 'Autoverzekering'.
   WHEN 'B'. lv_tekst = 'Brandverzekering'.
   WHEN OTHERS. lv_tekst = 'Onbekend'.
ENDCASE.

WHEN OTHERS is het vangnet: "in alle overige gevallen". Handig om te zien wat er gebeurt met waarden die niemand had voorzien.

LOOP — herhaling (herken je van sectie 3)

Zoals gezien loopt LOOP AT ... ENDLOOP door de rijen van een interne tabel. Vaak zit er ín de lus weer een IF — dan wordt per rij een keuze gemaakt:

LOOP AT lt_polissen INTO ls_polis.
   IF ls_polis-premie = 0.
      " markeer polis zonder premie
   ENDIF.
ENDLOOP.

Lees: "Voor elke polis: als de premie 0 is, doe iets." De - in ls_polis-premie betekent "het veld premie van die rij". Zo lees je: rij → veld.

Zo verandert code in een gesprek

Zodra je een IF/CASE herkent, kun je de regel in gewone taal navertellen en toetsen bij de business: "klopt het dat bedragen boven 10.000 handmatig gecontroleerd worden?" Dat is precies de brug die een BA slaat — je vertaalt code terug naar procesregels.

Controlevragen
1Vertel in gewone taal wat dit doet: IF lv_bedrag > 10000. ... ELSE. ... ENDIF.Toon antwoord
Het maakt een keuze op basis van het bedrag: is het groter dan 10.000, dan het ene pad (bv. handmatige controle), anders het andere (automatisch akkoord). Dat is een businessregel die je direct bij de proceseigenaar kunt verifiëren.
2Wat betekent WHEN OTHERS in een CASE?Toon antwoord
Het is het vangnet: "in alle overige gevallen die niet expliciet genoemd zijn". Het toont wat er gebeurt met onvoorziene of onbekende waarden — vaak interessant voor edge cases.
3Wat betekent de - in ls_polis-premie?Toon antwoord
Het verwijst naar het veld premie binnen de rij ls_polis. Lees het als "rij → kolom": het premieveld van de polis waar de lus nu mee bezig is.
06

Debugger & waar jij stopt

⏱ 35 min

De debugger: code in slow motion

De ABAP-debugger laat een programma stap voor stap uitvoeren in plaats van in één klap. Je ziet de code regel voor regel aflopen én de actuele waarde van elke variabele op dat moment. Voor een BA is dat goud: je ziet met eigen ogen welke data door welke logica gaat — vaak overtuigender dan welke uitleg ook.

Verwachting bijstellen

Debuggen op productie is vaak aan strikte autorisaties gebonden en gebeurt doorgaans mét een ontwikkelaar erbij. Het doel hier is dat je snapt wat de debugger je toont en gerichte vragen kunt stellen — niet dat je zelf onbegeleid in productie gaat debuggen.

Drie begrippen die je nodig hebt

BegripWat het isWaarom nuttig voor jou
BreakpointEen "stopstreep" die je op een regel zet; het programma pauzeert zodra het daar komt.Je kiest precies de plek waar je wilt kijken (bv. waar een bedrag berekend wordt).
Stap voor stapKnoppen om telkens één regel verder te gaan (single step / execute).Je volgt de logica in de volgorde waarin ze echt gebeurt — inclusief welke IF-tak genomen wordt.
Variabele bekijkenDe actuele waarde van een variabele of interne tabel op dat moment tonen.Je ziet de echte data: klopt de klant, het bedrag, de status — of gaat het hier al mis?

Waarom dit voor analyse zo krachtig is

  • "Werkt niet" wordt concreet. Zet een breakpoint waar het misgaat en je ziet exact welke waarde onverwacht is — dat verandert een vaag ticket in een scherpe bevinding.
  • Je verifieert businessregels live. Loopt de code écht door de "handmatige controle"-tak bij bedragen boven 10.000? De debugger laat het je zien.
  • Je overdracht wordt beter. "Bij deze order pakt hij de ELSE-tak terwijl we A verwachtten, en lv_bedrag is dan 9.999" is voor een ontwikkelaar goud waard.

Waar de BA stopt en de developer begint

De grens is geen muur maar een overdrachtsmoment. Ruwe vuistregel:

Dit doe je zelf (lezen & analyseren)Dit draag je over (schrijven & wijzigen)
Herkennen wát code doet: SELECT, LOOP, IF/CASE.Code aanpassen of nieuw schrijven.
Vaststellen uit wélke tabel data komt (FROM).Performance-tuning, JOINs, complexe queries herstructureren.
Een businessregel uit een IF/CASE navertellen en toetsen.Beoordelen of een wijziging elders iets breekt (technische impact).
Met een breakpoint een concrete waarde vaststellen.Debuggen in productie zonder begeleiding/autorisatie.
Een scherpe, onderbouwde bevinding formuleren.De daadwerkelijke fix bouwen, testen en transporteren.
Ken je grens — dat is een kracht

Stoppen op tijd is geen tekortkoming; het is professioneel. Zodra je twijfelt of iets ergens anders doorwerkt, of zodra er gewijzigd moet worden, is dat het moment voor de ontwikkelaar. Jouw waarde zit in de scherpe, goed onderbouwde vraag die je meegeeft — niet in zelf de code veranderen.
