01

Waarom Milan leert scripten & de shebang

⏱ 10 min
Casus

Milan heeft de afgelopen weken steeds dezelfde reeks commando's met de hand uitgevoerd op het Rapportagecluster: schijfruimte checken, oude logbestanden opruimen, de status van een dienst controleren, een rapport wegschrijven met datum in de bestandsnaam. Fenna ziet hem dat voor de derde keer typen en zegt: "Alles wat je twee keer met de hand doet, verdient een script. Niet omdat het sneller is — omdat het dan getest en herhaalbaar is."

Dat is de kern van bash-scripting: van losse commando's naar een bestand dat je uitvoert, dat zich elke keer hetzelfde gedraagt, en dat je kunt controleren voordat het schade aanricht. Dit deel behandelt de bouwstenen — variabelen, voorwaarden, lussen, functies en exit codes — die samen negentig procent van de scripts vormen die u in beheerwerk tegenkomt. Voor LFCS is dit direct examenstof: het praktijkexamen vraagt regelmatig om een kort script dat een taak automatiseert of een conditie afhandelt.

Elk bash-script begint met een shebang, de regel die het besturingssysteem vertelt welke interpreter het bestand moet uitvoeren:

#!/bin/bash

Dit moet de allereerste regel zijn, zonder lege regel of spatie ervoor. #!/bin/bash is de gangbare keuze; #!/usr/bin/env bash is een alternatief dat de eerste bash in $PATH gebruikt en daarmee iets draagbaarder is tussen systemen.

Een script uitvoerbaar maken en starten:

chmod +x rapport-check.sh
./rapport-check.sh

Zonder uitvoerrechten kunt u een script ook direct aan de interpreter meegeven, zonder chmod:

bash rapport-check.sh

Het verschil is relevant voor LFCS: ./rapport-check.sh vereist het executabele bit én een geldige shebang; bash rapport-check.sh negeert beide en start altijd een nieuwe bash-shell met het script als invoer.

Controlevraag

Uit Werkboek deel 21, Opdracht 21.1 + Uitwerking 21.1

1Schrijf een script groet.sh met correcte shebang, dat "Hallo Milan, vandaag is <datum>." afdrukt, en draai het op twee manieren. Wat is het verschil tussen die twee manieren?Toon antwoord
#!/bin/bash
naam="Milan"
datum="$(date +%F)"
echo "Hallo ${naam}, vandaag is ${datum}."
chmod +x groet.sh
./groet.sh
bash groet.sh

Beide aanroepen geven dezelfde uitvoer. Het verschil: ./groet.sh vereist het uitvoerbare bit (chmod +x) en gebruikt de shebang om de interpreter te bepalen; bash groet.sh negeert beide en start expliciet een bash-proces met het script als invoer.

02

Variabelen, quoting en invoer

⏱ 12 min

Variabelen in bash krijgen geen spaties rond het =-teken en worden aangeroepen met een $-prefix:

cluster="rapportagecluster"
aantal_nodes=4
echo "Cluster: $cluster, nodes: $aantal_nodes"

Gebruik ${variabele} wanneer de naam direct tegen andere tekst aan staat, om verwarring te voorkomen:

logbestand="rapport"
echo "${logbestand}_$(date +%F).log"

Quoting is geen stijlkeuze maar correctheid. Dubbele aanhalingstekens laten variabele-expansie toe maar behouden spaties; enkele aanhalingstekens onderdrukken alle expansie:

pad="/var/log/rapportage cluster"
ls "$pad"      # correct: één argument, ook met spatie in het pad
ls $pad         # fout: wordt twee argumenten, ls zoekt twee losse mappen

Fenna's vuistregel voor Milan: quote elke variabele, tenzij je een expliciete reden hebt om het niet te doen.

Positionele parameters geven toegang tot argumenten waarmee het script is aangeroepen:

#!/bin/bash
echo "Scriptnaam: $0"
echo "Eerste argument: $1"
echo "Aantal argumenten: $#"
echo "Alle argumenten: $@"

Speciale variabelen die u veel gebruikt: $? (exit code van het laatst uitgevoerde commando), $$ (PID van het huidige script) en $USER (ingelogde gebruiker, een omgevingsvariabele).

Voor interactieve scripts leest read invoer van de gebruiker:

read -p "Naam van het rapport: " rapportnaam
echo "U koos: $rapportnaam"

Rekenkundige bewerkingen gebeuren met $(( )):

schijfruimte_gb=120
gebruikt_gb=87
vrij_gb=$(( schijfruimte_gb - gebruikt_gb ))
echo "Vrije ruimte: ${vrij_gb} GB"
03

Voorwaardelijke logica: if, elif, else

⏱ 10 min

De klassieke vorm gebruikt [ ], een alias voor het commando test:

#!/bin/bash
vrij_gb=8

if [ "$vrij_gb" -lt 10 ]; then
    echo "Waarschuwing: minder dan 10 GB vrij"
elif [ "$vrij_gb" -lt 20 ]; then
    echo "Let op: minder dan 20 GB vrij"
else
    echo "Schijfruimte in orde"
fi

Let op de spaties: [ "$vrij_gb" -lt 10 ] moet spaties hebben direct na [ en direct voor ], anders geeft bash een syntaxfout. De numerieke vergelijkingsoperatoren zijn -eq, -ne, -lt, -le, -gt, -ge.

Sinds bash 4 is [[ ]] de moderne variant: veiliger met quoting, ondersteunt patroonmatching en logische operatoren &&/|| binnen de expressie:

status="actief"

if [[ "$status" == "actief" && "$vrij_gb" -gt 5 ]]; then
    echo "Systeem gezond"
fi

Veelgebruikte bestandstests, die u in beheerscripts voortdurend tegenkomt:

if [ -f /etc/rapportage.conf ]; then
    echo "Configuratiebestand bestaat"
fi

if [ -d /var/log/rapportage ]; then
    echo "Logmap bestaat"
fi

if [ ! -w /var/log/rapportage ]; then
    echo "Geen schrijfrechten op logmap"
fi

-f test op een gewoon bestand, -d op een map, -x op uitvoerbaarheid, -w op schrijfrechten, -z op een lege string en -n op een niet-lege string. ! keert de test om.

Controlevraag

Uit Werkboek deel 21, Opdracht 21.2 + Uitwerking 21.2

1Schrijf de juiste if-conditie voor: (a) bestaat /etc/rapportage.conf? (b) is /var/log/rapportage schrijfbaar? (c) is aantal_fouten groter dan 0? (d) is omgeving gelijk aan "productie"?Toon antwoord
# a
if [ -f /etc/rapportage.conf ]; then
    echo "Bestand bestaat"
fi

# b
if [ -w /var/log/rapportage ]; then
    echo "Map is schrijfbaar"
fi

# c
if [ "$aantal_fouten" -gt 0 ]; then
    echo "Er zijn fouten"
fi

# d
if [ "$omgeving" == "productie" ]; then
    echo "Dit is productie"
fi

Met [[ ]] is d) ook te schrijven als if [[ "$omgeving" == "productie" ]]; then; functioneel identiek voor een simpele stringvergelijking, maar [[ ]] voorkomt problemen als $omgeving leeg of ongequote zou zijn.

04

Lussen: for, while, until

⏱ 10 min

De for-lus itereert over een lijst:

for logfile in /var/log/rapportage/*.log; do
    echo "Verwerk: $logfile"
done

Of over een expliciete reeks:

for node in node1 node2 node3 node4; do
    echo "Controleer $node"
    ssh "$node" uptime
done

while herhaalt zolang een conditie waar is — bruikbaar om regel voor regel door een bestand te lezen:

while read -r regel; do
    echo "Verwerk regel: $regel"
done < /etc/hosts

until is het spiegelbeeld van while en loopt tot een conditie waar wordt:

teller=0
until [ "$teller" -ge 5 ]; do
    echo "Poging $teller"
    teller=$(( teller + 1 ))
done

Milan gebruikt dit patroon om te wachten tot een dienst opstart:

while ! systemctl is-active --quiet rapportage-api; do
    echo "Wachten op rapportage-api..."
    sleep 2
done
echo "rapportage-api is actief"
05

Functies

⏱ 10 min

Functies groeperen herbruikbare logica. Gebruik local voor variabelen binnen een functie, zodat ze niet lekken naar de rest van het script:

controleer_schijfruimte() {
    local mountpoint="$1"
    local drempel="$2"
    local vrij
    vrij=$(df --output=avail "$mountpoint" | tail -1 | tr -d ' ')

    if [ "$vrij" -lt "$drempel" ]; then
        echo "Waarschuwing: $mountpoint heeft minder dan $drempel KB vrij"
        return 1
    fi

    return 0
}

controleer_schijfruimte "/var" 1000000

Een functie geeft een status terug via return (0 tot 255, bedoeld als exit code) en tekstuele uitvoer via echo, opgevangen met command substitution:

huidige_datum() {
    date +%F
}

vandaag="$(huidige_datum)"
echo "Rapport van $vandaag"
06

Exit codes en foutafhandeling

⏱ 12 min

Elk commando in Linux geeft bij afsluiten een exit code terug: 0 betekent succes, elke waarde van 1 tot 255 betekent een fout, met per commando eigen betekenissen. $? bevat de exit code van het laatst uitgevoerde commando:

grep "ERROR" /var/log/rapportage/verwerking.log
if [ $? -eq 0 ]; then
    echo "Fouten gevonden in het logbestand"
fi

Idiomatischer is het direct testen van het commando zelf:

if grep -q "ERROR" /var/log/rapportage/verwerking.log; then
    echo "Fouten gevonden in het logbestand"
fi

Een script sluit standaard af met de exit code van het laatste commando, maar u kunt dat expliciet sturen met exit:

if [ ! -f /etc/rapportage.conf ]; then
    echo "Fout: configuratiebestand ontbreekt" >&2
    exit 1
fi

echo "Configuratie gevonden, doorgaan"
exit 0

>&2 stuurt de foutmelding naar stderr in plaats van stdout — belangrijk in scripts die door andere scripts of cron worden aangeroepen, zodat foutmeldingen apart van reguliere uitvoer te onderscheiden zijn.

Voor productiescripts raadt Fenna een vaste kop aan:

#!/bin/bash
set -euo pipefail

set -e stopt het script zodra een commando faalt (exit code ongelijk aan 0), in plaats van door te lopen met een half uitgevoerd script. set -u laat het script stoppen bij gebruik van een niet-gedefinieerde variabele — vangt typefouten in variabelenamen. set -o pipefail zorgt dat een pipeline faalt zodra één van de onderdelen faalt, niet alleen het laatste. Milan zet dit inmiddels standaard boven elk script dat hij voor het Rapportagecluster schrijft, sinds een vergeten sudo in een niet-beveiligd script stilzwijgend een lege variabele opleverde en drie logbestanden overschreef.

Controlevraag

Uit Werkboek deel 21, Opdracht 21.6 (reflectie)

1Fenna toont een script zonder set -euo pipefail: cd /var/log/rapportage-oud gevolgd door rm -rf *. Wat gaat er mis als die map niet bestaat, en welke twee onafhankelijke beveiligingen voorkomen dat?Toon antwoord
Zonder set -e en zonder controle op het bestaan van de map, faalt cd /var/log/rapportage-oud stilzwijgend als de map niet bestaat — bash meldt de fout op stderr maar het script gaat gewoon door naar de volgende regel. rm -rf * wordt dan uitgevoerd in de map waarin het script toevallig werd gestart, met alle gevolgen van dien. Twee onafhankelijke beveiligingen: set -euo pipefail laat het script stoppen zodra cd faalt; een expliciete -d-test met eigen foutmelding faalt vóórdat cd zelfs geprobeerd wordt en maakt duidelijk waarom het script stopt.
#!/bin/bash
set -euo pipefail

doelmap="/var/log/rapportage-oud"

if [ ! -d "$doelmap" ]; then
    echo "Fout: $doelmap bestaat niet, script stopt" >&2
    exit 1
fi

cd "$doelmap"
rm -rf -- *

De expliciete -d-test is de robuustere van de twee, omdat hij blijft werken in situaties waarin set -e om subtiele redenen niet toeslaat (zoals binnen een if-conditie of een pipeline zonder pipefail).

07

Een compleet voorbeeld

⏱ 8 min

Een script dat Fenna als oefenmateriaal gebruikt: het ruimt logbestanden ouder dan een opgegeven aantal dagen op, met validatie en logging.

#!/bin/bash
set -euo pipefail

logmap="$1"
dagen="$2"

if [ -z "$logmap" ] || [ -z "$dagen" ]; then
    echo "Gebruik: $0  " >&2
    exit 1
fi

if [ ! -d "$logmap" ]; then
    echo "Fout: $logmap is geen bestaande map" >&2
    exit 1
fi

aantal_verwijderd=0

find "$logmap" -name "*.log" -mtime "+$dagen" -print0 | \
while IFS= read -r -d '' bestand; do
    rm "$bestand"
    aantal_verwijderd=$(( aantal_verwijderd + 1 ))
    echo "Verwijderd: $bestand"
done

echo "Opschoning van $logmap voltooid"

Aanroep: ./opschonen.sh /var/log/rapportage 30 verwijdert .log-bestanden ouder dan 30 dagen. De find ... -print0 met read -r -d '' verwerkt bestandsnamen met spaties correct — een detail dat in het LFCS-examen regelmatig als valkuil terugkomt.
