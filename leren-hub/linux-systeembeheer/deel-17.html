01

Wat zijn dotfiles?

⏱ 10 min

Bestanden en mappen waarvan de naam met een punt begint, zijn in Linux verborgen voor een gewone ls (u heeft ls -a nodig om ze te zien). Veel programma's — waaronder de shell zelf — gebruiken zulke verborgen bestanden in uw homedirectory om instellingen op te slaan: .bashrc, .bash_profile, .vimrc, .gitconfig, .ssh/config. Samen heten deze dotfiles.

Voor bash zijn twee bestanden het belangrijkst:

  • ~/.bashrc wordt gelezen bij elke nieuwe interactieve, niet-login shell — praktisch: elke keer dat u een nieuw terminalvenster of een nieuwe tmux-pane opent.
  • ~/.bash_profile (of bij afwezigheid daarvan ~/.profile) wordt gelezen bij een login shell — praktisch: wanneer u via SSH inlogt of een tekstconsole aanmeldt.

Dit onderscheid verwart bijna iedereen bij eerste kennismaking. De praktische oplossing, die u in de meeste Ubuntu-installaties al standaard aantreft, is dat .bash_profile (of .profile) aan het eind .bashrc insourcet:

# in ~/.profile
if [ -n "$BASH_VERSION" ]; then
    if [ -f "$HOME/.bashrc" ]; then
        . "$HOME/.bashrc"
    fi
fi

Zo hoeft u zich in de praktijk vooral druk te maken om .bashrc: daar zet u aliassen, functies, promptinstellingen en de meeste omgevingsvariabelen.

Casus

Milan werkt op vier plekken met een shell: zijn Raspberry Pi, de VM's op zijn laptop, en straks het Rapportagecluster. Fenna's advies: "Bouw je .bashrc op alsof je hem morgen naar een vijfde machine kopieert. Alles wat je handmatig moet nadoen na het kopiëren, ben je een keer te veel vergeten."

02

Aliassen

⏱ 8 min

Een alias is een verkorte of aangepaste vorm van een bestaand commando:

alias ll='ls -la'
alias grep='grep --color=auto'
alias ..='cd ..'
alias update='sudo apt update && sudo apt upgrade -y'

Zet u deze regels in ~/.bashrc, dan zijn ze bij elke nieuwe shell beschikbaar. Om ze direct te laden zonder een nieuwe terminal te openen:

source ~/.bashrc

Aliassen bekijken: alias (zonder argumenten toont alle actieve aliassen). Een alias tijdelijk negeren en het originele commando aanroepen: zet een backslash ervoor, bijvoorbeeld \ls.

Voor logica die verder gaat dan een simpele vervanging — bijvoorbeeld een argument doorgeven — gebruikt u een shell-functie in plaats van een alias:

mkcd() {
    mkdir -p "$1" && cd "$1"
}

Deze functie maakt een map aan (inclusief eventuele bovenliggende mappen, dankzij -p) en navigeert er direct naartoe.

03

De prompt aanpassen

⏱ 10 min

De inhoud van de shell-prompt wordt bepaald door de variabele PS1. Standaard toont Ubuntu Server iets als gebruiker@host:~$. PS1 bestaat uit letterlijke tekst gecombineerd met escape-codes:

CodeBetekenis
\ugebruikersnaam
\hhostnaam (kort)
\whuidige werkmap (volledig pad, ~ voor de homedirectory)
\Walleen de laatste mapnaam
\ttijd (24-uurs)
\$$ voor gewone gebruiker, # voor root

Een voorbeeld dat gebruikersnaam, host en werkmap toont, met kleur voor de hostnaam:

PS1='\u@\[\033[1;32m\]\h\[\033[0m\]:\w\$ '

De \[ en \] markeren het begin en einde van niet-zichtbare tekens (de kleurcodes), zodat bash de regellengte correct berekent — zonder die markering springt de cursor bij regelterugloop op de verkeerde plek.

Casus

Op het Rapportagecluster werkt Milan soms als zichzelf, soms met sudo -i als root. Fenna raadt aan de prompt zo in te richten dat rootsessies onmiskenbaar rood zijn — een simpele maatregel die voorkomt dat je per ongeluk een productieactie uitvoert in de veronderstelling dat je nog je eigen account bent.

Controlevraag

Uit Werkboek deel 17, Opdracht 17.2 + Uitwerking 17.2

1Pas PS1 aan zodat de prompt gebruikersnaam, hostnaam in groen, huidige werkmap en $/# toont. Wat verschijnt er in de prompt na sudo -i?Toon antwoord
PS1='\u@\[\033[1;32m\]\h\[\033[0m\]:\w\$ '

Controlepunt: na sudo -i toont de prompt root@host:~# — het slotteken # wijst op root; het slotteken $ op een gewone gebruiker. Wie extra visuele nadruk wil, kleurt ook \$ rood binnen een if [ "$EUID" -eq 0 ]-check, maar dat is niet vereist voor deze opdracht.

04

Omgevingsvariabelen die het waard zijn om te zetten

⏱ 8 min

PATH bepaalt in welke mappen de shell zoekt naar uitvoerbare programma's. Een eigen scriptmap toevoegen:

export PATH="$HOME/bin:$PATH"

EDITOR (en vaak ook VISUAL) bepaalt welke teksteditor programma's als crontab -e, git commit (zonder -m) of visudo openen:

export EDITOR=vim

Geschiedenisinstellingen: HISTSIZE (aantal regels in het geheugen van de huidige sessie) en HISTFILESIZE (aantal regels bewaard in ~/.bash_history) los van elkaar instellen, en dubbele/overbodige regels weren met HISTCONTROL:

export HISTSIZE=5000
export HISTFILESIZE=10000
export HISTCONTROL=ignoredups:erasedups

ignoredups slaat een commando niet op als het identiek is aan het vorige; erasedups verwijdert eerdere identieke regels uit de geschiedenis zodat elk commando maar één keer voorkomt.

05

Dotfiles overdraagbaar maken

⏱ 12 min

Zodra .bashrc meer bevat dan een paar regels, wilt u hem niet opnieuw typen op elke machine. Twee gangbare aanpakken:

Een dotfiles-repository met symlinks. U zet uw dotfiles in een gewone Git-repository (bijvoorbeeld ~/dotfiles/bashrc) en maakt op elke machine een symbolische link:

ln -s ~/dotfiles/bashrc ~/.bashrc

Wijzigingen in ~/.bashrc zijn dan automatisch wijzigingen in de repository, en u kunt ze committen en op een andere machine ophalen met git pull.

Een install.sh-script dat bij het klonen van de dotfiles-repository automatisch alle symlinks aanmaakt, is de gebruikelijke volgende stap zodra u meer dan drie of vier dotfiles beheert — dat valt buiten de scope van dit deel, maar is het logische vervolg als u dit patroon eigen maakt.
