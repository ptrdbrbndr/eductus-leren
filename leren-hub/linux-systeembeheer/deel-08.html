01

Het probleem dat een pakketbeheerder oplost

⏱ 8 min

Milan is gewend software op Windows te installeren door een .exe te downloaden en "Volgende, Volgende, Voltooien" te klikken. Fenna legt hem uit waarom dat op een Linux-server geen goed idee is: elk los gedownload installatieprogramma brengt zijn eigen versie van afhankelijkheden mee, houdt zelf niets bij over updates, en laat bij verwijderen vaak rommel achter.

Een pakketbeheerder (package manager) lost dit centraal op: hij houdt een catalogus bij van beschikbare software (het repository), controleert en installeert afhankelijkheden automatisch, registreert precies welke bestanden bij welk pakket horen, en kan software dus ook weer volledig en netjes verwijderen. Op serverniveau is dit niet optioneel maar noodzakelijk — een productieomgeving met tientallen handmatig geïnstalleerde programma's zonder centrale registratie is binnen een jaar onbeheersbaar.

Ubuntu (en Debian, waarop Ubuntu is gebaseerd) gebruikt APT (Advanced Package Tool) met pakketten in het .deb-formaat. Dit is de hoofdlijn van deze cursus.

02

apt: de basiscommando's

⏱ 15 min

Alle commando's die het systeem daadwerkelijk wijzigen, vereisen sudo (root-rechten — deel 11 gaat hier dieper op in; voor nu: typ sudo vóór commando's die iets installeren, verwijderen of bijwerken).

sudo apt update              # ververst de lokale lijst van beschikbare pakketten en versies
sudo apt upgrade             # installeert beschikbare updates voor geïnstalleerde pakketten
sudo apt install nginx       # installeert het pakket "nginx"
sudo apt remove nginx        # verwijdert nginx, laat configuratiebestanden staan
sudo apt purge nginx         # verwijdert nginx inclusief configuratiebestanden
sudo apt autoremove          # verwijdert pakketten die als afhankelijkheid zijn binnengehaald en nergens meer nodig zijn

apt update is geen upgrade. Dit is de meest voorkomende misvatting bij nieuwe Linux-beheerders. apt update haalt alleen de lijst met beschikbare versies op bij de geconfigureerde repositories — er wordt geen enkel pakket op uw systeem aangeraakt. Pas apt upgrade installeert daadwerkelijk nieuwere versies van al geïnstalleerde software. De twee horen altijd na elkaar:

sudo apt update && sudo apt upgrade -y

Het &&-teken (behandeld in deel 13) zorgt dat upgrade alleen start als update succesvol was; -y beantwoordt de bevestigingsvraag automatisch met "ja", nuttig in scripts maar gebruik dit bewust — op een systeem dat u nog niet goed kent, is het eerste keer zonder -y verstandiger, zodat u ziet wat er precies wordt gewijzigd.

remove versus purge

remove verwijdert het pakket maar laat configuratiebestanden staan (statuscode rc in dpkg -l); purge verwijdert ook die configuratie. Gebruik remove bij tijdelijk weghalen met kans op herinstallatie, purge bij definitief opschonen van een server.

Controlevragen

Uit Werkboek deel 8, Opdracht 8.1 en 8.3

1Waarom kan apt upgrade "0 upgraded" tonen terwijl er wel degelijk updates beschikbaar zijn?Toon antwoord
Omdat apt update niet vooraf is uitgevoerd: de lokale pakketlijst is dan verouderd, waardoor apt denkt dat er niets nieuws is. apt update zelf installeert niets — het ververst alleen de lijst — pas de combinatie sudo apt update && sudo apt upgrade -y toont en installeert de daadwerkelijk beschikbare updates.
2Na sudo apt remove tree toont dpkg -l | grep tree een regel die begint met rc. Wat betekent dat, en hoe verwijdert u dat restant volledig?Toon antwoord
rc staat voor "removed, config remains": het pakket zelf is weg, maar configuratiebestanden staan nog op het systeem. Met sudo apt purge tree verwijdert u ook die resterende configuratie, waarna de regel volledig uit dpkg -l verdwijnt.
03

Zoeken en pakketinformatie opvragen

⏱ 10 min
apt search grafana           # zoekt pakketten waarvan naam of omschrijving "grafana" bevat
apt show prometheus          # toont details van een specifiek pakket: versie, grootte, afhankelijkheden, omschrijving
apt list --installed         # toont alle geïnstalleerde pakketten
apt list --installed | grep python3   # filtert die lijst op "python3"
dpkg -L nginx                # toont welke bestanden het pakket nginx op schijf heeft geplaatst
dpkg -S /usr/bin/nginx       # zoekt uit bij welk pakket een bestand hoort (omgekeerde vraag)

apt is het gebruiksvriendelijke commando voor dagelijks werk; dpkg is het onderliggende, lagere-niveau gereedschap dat met individuele .deb-pakketten werkt. U gebruikt dpkg vooral om vragen te beantwoorden over wat er al op het systeem staat.

Controlevraag

Uit Werkboek deel 8, Opdracht 8.2

1U installeerde het pakket tree. Met welke twee commando's vindt u het uitvoerbare bestand op schijf, en hoe bevestigt u dat dit bestand bij het pakket tree hoort?Toon antwoord
dpkg -L tree toont een lijst paden, waaronder typisch /usr/bin/tree — dit is het uitvoerbare programma zelf; de overige regels zijn documentatie- en manualbestanden. Met dpkg -S /usr/bin/tree bevestigt u vervolgens met een regel als tree: /usr/bin/tree dat dit bestand inderdaad bij het pakket tree hoort — de omgekeerde vraag van -L.
04

Repositories: waar komt software vandaan?

⏱ 10 min

Ubuntu haalt pakketten op uit repositories: online (of lokale) verzamelingen van pakketten die APT als vertrouwde bron beschouwt. Welke repositories actief zijn, staat in /etc/apt/sources.list en in bestanden onder /etc/apt/sources.list.d/.

cat /etc/apt/sources.list
ls /etc/apt/sources.list.d/

Elke repository is digitaal ondertekend; APT controleert bij apt update of pakketten inderdaad van de opgegeven bron komen en niet onderweg zijn gemanipuleerd. Software toevoegen buiten de standaardrepositories om (bijvoorbeeld de officiële Grafana- of Docker-repository) betekent in de praktijk: een .list-bestand toevoegen én de bijbehorende ondertekeningssleutel vertrouwen. Dit onderwerp — inclusief het zelf inrichten van een repository — komt uitgebreid terug in deel 24 (pakketbeheer verdieping); voor nu is het voldoende te weten dát dit mechanisme bestaat en waarom het niet verstandig is een repository toe te voegen die u niet vertrouwt.

Fenna's regel

"Voeg nooit een repository toe die je niet kunt uitleggen aan een collega."

Controlevraag

Uit Werkboek deel 8, Opdracht 8.4

1Welke soorten componenten treft u typisch aan in /etc/apt/sources.list op een Ubuntu Server LTS-installatie, naast de codenaam van de release?Toon antwoord
Naast de codenaam (bijvoorbeeld jammy voor 22.04 of noble voor 24.04) staan er componenten als main (door Canonical ondersteunde open-sourcesoftware), universe (door de gemeenschap onderhouden), restricted (gesloten stuurprogramma's) en multiverse (software met beperkingen, bijvoorbeeld licentie), plus aparte regels voor -security en -updates. Op recentere Ubuntu-versies (24.04+) kan deze informatie ook in een .sources-bestand in DEB822-formaat staan in plaats van in het klassieke sources.list-formaat — beide zijn correct, alleen technisch anders genoteerd.
05

Andere distributies: dnf en pacman

⏱ 12 min

LPIC-1 en Linux+ zijn distributieneutrale certificeringen: de examens veronderstellen dat u weet dat er meerdere pakketbeheerders bestaan, ook als u dagelijks met APT werkt. De twee belangrijkste alternatieven:

dnf (Red Hat, Fedora, Rocky Linux, AlmaLinux) — werkt met .rpm-pakketten:

sudo dnf check-update    # equivalent van apt update (lijst verversen)
sudo dnf upgrade         # equivalent van apt upgrade
sudo dnf install nginx   # equivalent van apt install
sudo dnf remove nginx    # equivalent van apt remove
dnf search grafana       # equivalent van apt search

pacman (Arch Linux en afgeleiden) — kent geen apart update/upgrade-onderscheid; -Syu doet beide in één stap:

sudo pacman -Syu          # synchroniseert pakketlijst én werkt het systeem bij, in één commando
sudo pacman -S nginx      # installeert nginx
sudo pacman -R nginx      # verwijdert nginx
pacman -Ss grafana        # zoekt naar grafana

De onderliggende gedachte is bij alle drie identiek: een centrale, digitaal ondertekende catalogus, automatische afhankelijkheidsresolutie, en een duidelijke scheiding tussen "wat is beschikbaar" en "wat installeer ik nu". Het examen kan u vragen een apt-commando te herkennen naast zijn dnf- of pacman-equivalent — u hoeft ze niet allemaal uit uw hoofd te kennen, wel de basislogica te herkennen.

Actieaptdnfpacman
Pakketlijst verversenapt updatednf check-update(onderdeel van -Syu)
Updates installerenapt upgradednf upgradepacman -Syu
Pakket installerenapt install nginxdnf install nginxpacman -S nginx
Pakket verwijderenapt remove nginxdnf remove nginxpacman -R nginx
Zoekenapt search grafanadnf search grafanapacman -Ss grafana
Controlevraag

Uit Werkboek deel 8, Opdracht 8.5

1Waarom doet pacman -Syu in één commando wat apt in twee commando's doet?Toon antwoord
Dit is een bewust ontwerpverschil, geen fout: Arch/pacman combineert het verversen van de pakketlijst (het apt update-equivalent) en het daadwerkelijk installeren van updates (het apt upgrade-equivalent) in één stap, terwijl APT deze twee handelingen bewust gescheiden houdt.
