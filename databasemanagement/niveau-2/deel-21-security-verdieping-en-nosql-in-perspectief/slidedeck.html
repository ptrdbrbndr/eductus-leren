Slide 1 — Titel

Security-verdieping en NoSQL

Niveau 2 — Deel 21

Voorlaatste dagdeel van dit niveau.

Slide 2 — Waar deel 9 ophield

Rollen, GRANT/REVOKE, een eerste RLS-regel.

Sindsdien bijgekomen: partitionering, replicatie, pgaudit — allemaal dingen die rechten en beleid complexer maken.

Slide 3 — Twee policies

CREATE POLICY p1 ON t FOR SELECT USING (status = 'actief');
CREATE POLICY p2 ON t FOR SELECT USING (regio = 'noord');

Een rij: status='actief', regio='zuid'.

Zichtbaar of niet?

Notities: laat de zaal gokken.

Slide 4 — Zichtbaar.

Permissieve policies worden

met OR gecombineerd.

Niet: “moet aan beide voldoen.” Wél: “voldoet aan minstens één.”

Slide 5 — De harde grens

CREATE POLICY kantooruren ON t
    AS RESTRICTIVE
    USING (extract(hour FROM now()) BETWEEN 8 AND 18);

Restrictief = AND, bovenop de permissieve OR. Kan alleen inperken, nooit verruimen.

Slide 7 — RLS is geen gratis beveiliging

De policy-voorwaarde is een extra WHERE-clausule voor de planner. Zonder index: extra scan.

CREATE INDEX ON dienstverband (werkgever_id);

Slide 8 — De valkuil

-- traag: per rij een functie-aanroep
USING (werkgever_id = huidige_werkgever())

-- snel: directe sessie-instelling
USING (werkgever_id = current_setting('app.werkgever_id')::int)

Slide 9 — Waarom dit nu pas opvalt

In deel 9: 100 rijen. Onmerkbaar.

Vandaag: 200.000 rijen.

Dezelfde overhead, vermenigvuldigd — de schaal-les uit deel 12, opnieuw.

Slide 12 — pgcrypto

UPDATE deelnemer
SET rekeningnummer_enc = pgp_sym_encrypt(rekeningnummer, 'sleutel');

Probeer op de versleutelde waarde te zoeken.

Notities: laat het mislukken vóór de uitleg.

Slide 13 — Waarom het mislukt

Elke versleuteling van dezelfde tekst levert een andere cijfertekst op.

Versleuteld ≠ doorzoekbaar versleuteld.

Slide 14 — De sleutel

Nooit in de query.

Nooit in de applicatiecode.

Nooit in de database zelf.

Extern sleutelbeheer — anders is de versleuteling zinledig tegen precies het risico waar hij tegen moet beschermen.

Slide 16 — hostssl versus host

hostssl  meridiaan  all  0.0.0.0/0  scram-sha-256

host = SSL optioneel. hostssl = verplicht.

sslmode=verify-full — controleert ook of het certificaat bij de juiste server hoort.

Slide 17 — Onderweg vs. in rust

Onderweg — beschermt tegen afluisteren In rust — beschermt tegen fysieke toegang

een gecompromitteerde rol met

geldige toegang.

Slide 19 — Rolhiërarchie

CREATE ROLE lezer_deelnemer NOLOGIN;
GRANT SELECT ON deelnemer TO lezer_deelnemer;

CREATE ROLE klantenservice LOGIN PASSWORD '...';
GRANT lezer_deelnemer TO klantenservice;

Eén recht wijzigen op de groep → werkt door naar iedereen.

Slide 20 — DEFAULT PRIVILEGES

ALTER DEFAULT PRIVILEGES IN SCHEMA meridiaan_prod
    GRANT SELECT ON TABLES TO lezer_deelnemer;

Zonder dit: een nieuwe tabel heeft geen rechten — iemand moet er expliciet aan denken. Elke keer.

Slide 23 — SECURITY DEFINER, herzien

Draait met de rechten van de eigenaar.

Wat als de aanroeper zijn eigen

search_path manipuleert?

Slide 24 — De kaping

Functie zoekt een tabel zonder schema-naam. Aanroeper zet zijn eigen schema eerst in het pad.

De functie raadpleegt de verkeerde tabel —

met de rechten van de eigenaar.

Slide 25 — De regel, zonder uitzondering

CREATE FUNCTION … SECURITY DEFINER
    SET search_path = meridiaan_prod, pg_catalog
    …

Elke SECURITY DEFINER-functie.

Geen uitzonderingen.
