Slide 6 — Praktijk: portaal-telemetrie

“Laatste honderd paginaweergaven van deelnemer X, nieuwste eerst”

CREATE TABLE portaal_bezoeken_per_deelnemer (
  deelnemer_id bigint,
  bezocht_op timestamp,
  pagina text,
  PRIMARY KEY (deelnemer_id, bezocht_op)
) WITH CLUSTERING ORDER BY (bezocht_op DESC);

Notities: deelnemer_id = partition key, bezocht_op = clustering key.

Slide 11 — De vraag uit deel 21

“Welke deelnemers delen een werkgever binnen twee schakels, via welke tussenliggende relaties”

Toen: onhandelbaar in SQL bij grote, diepe netwerken. Nu: uitgewerkt in Cypher.

Slide 12 — Directe collega’s in Cypher

MATCH (d1:Deelnemer {id: 4821})-[:WERKT_BIJ]->(w:Werkgever)<-[:WERKT_BIJ]-(d2:Deelnemer)
WHERE d1 <> d2
RETURN DISTINCT d2.naam, w.naam AS gedeelde_werkgever;

Notities: leg uit waarom WHERE d1 <> d2 nodig is.

Slide 13 — Binnen twee schakels

MATCH path = (d1:Deelnemer {id: 4821})-[:WERKT_BIJ|DEELNEEMT_AAN*1..2]-(d2:Deelnemer)
WHERE d1 <> d2
RETURN DISTINCT d2.naam, [r IN relationships(path) | type(r)] AS via;

Het pad is een eersteklas concept in de query — geen herhaalde join.
