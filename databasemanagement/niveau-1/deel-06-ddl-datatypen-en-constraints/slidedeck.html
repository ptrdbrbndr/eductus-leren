Slide 1 — Titel

DDL, datatypen

Niveau 1 — Deel 6

Deel 5 bedacht wat er zou moeten staan. Vandaag bouwen we het.

Slide 2 — Eerst dit

CREATE SCHEMA oefening;
SET search_path TO oefening, meridiaan, public;

Iedereen werkt in oefening.

Wie in meridiaan bouwt, sloopt de casus voor deel 7 t/m 10.

Notities: herhalen. Er is altijd iemand die het mist.

Slide 3 — De boodschap van vandaag

Elke regel die je niet

in de database vastlegt,

moet iemand anders onthouden.

Slide 4 — Datatypen: numeriek
integer Standaard geheel getal
bigint Sleutels van grote tabellen
numeric(p,s) Geld. Altijd.
real / double Wetenschappelijke metingen

Slide 5 — Nog één keer

SELECT 0.1::float + 0.2::float = 0.3::float;        -- false
SELECT 0.1::numeric + 0.2::numeric = 0.3::numeric;  -- true

Een cent verschil op 340.000 aanspraken is geen academisch punt.

Slide 6 — Datatypen: tekst

In PostgreSQL is text de standaard.

Geen prestatieverschil met varchar(n).

varchar(n) alleen als de lengte een echte bedrijfsregel is: KvK = 8, ISO-landcode = 2.

char(n) — vermijden (vult aan met spaties).

Slide 7 — varchar(100) voor een naam

Geen bedrijfsregel. Een schatting.

En dus een productiefout

die op iemand wacht.

Slide 8 — Datatypen: tijd

date · timestamptz · interval · daterange

Gebruik timestamptz, niet timestamp.

2026-10-25 02:30 in Nederland: welk van de twee?

Slide 9 — Rangetypen

daterange(DATE '2024-01-01', DATE '2024-07-01', '[)')
  @> DATE '2024-03-15'    -- true

'[)' = ondergrens inclusief, bovengrens exclusief

Eén waarde in plaats van twee kolommen — en het maakt slide 25 mogelijk.

Slide 10 — jsonb: wanneer wel

jsonb voor wat je bewaart.

Kolommen voor wat je gebruikt.

Wel: ruw bericht uit een koppelvlak, configuratieblok Niet: een adres — daar wil je op filteren, bewaken en historie voeren

Slide 11 — Opdracht 6.1

Datatypen kiezen

Slide 12 — Sleutelwaarden

-- aanbevolen
deelnemer_id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY

-- legacy
deelnemer_id serial PRIMARY KEY

GENERATED ALWAYS verbiedt een eigen waarde → geen sequentiebotsingen.

Slide 13 — Sequenties hebben gaten

Een teruggedraaide transactie geeft het nummer niet terug.

Vraagt de business om gatenloze nummering?

Beloof niets voordat je

de gevolgen hebt uitgelegd.

Slide 14 — Waarom in de database en niet in de code

  1. Er is nooit één applicatie — ook een importscript, ook psql
  2. Code wordt vervangen; gegevens blijven — 5 jaar tegen 20
  3. Gelijktijdigheid — “eerst kijken, dan invoegen” faalt onder belasting

Slide 15 — Vraag aan de zaal

Wie heeft er een bedrijfsregel

die alleen in applicatiecode staat?

Notities: één voorbeeld uitwerken. Wat gebeurt er als iemand die tabel met een script bijwerkt?

Slide 16 — De constrainttypen
NOT NULL Waarde verplicht
UNIQUE Geen duplicaten (NULL’s wel)
PRIMARY KEY UNIQUE + NOT NULL, één per tabel
FOREIGN KEY Verwijst naar bestaande rij
CHECK Regel binnen de eigen rij
EXCLUDE Verbiedt combinaties tussen rijen

Slide 17 — Voorspel

CREATE TEMP TABLE t (bedrag numeric CHECK (bedrag > 0));
INSERT INTO t VALUES (NULL);

Notities: de zaal verwacht een fout. Het gaat gewoon door.

Slide 18 — CHECK en NULL

Een CHECK die unknown oplevert wordt toegestaan.

CHECK vervangt NOT NULL niet.

Wil je beide? Schrijf beide.

Slide 19 — Twee dingen over FOREIGN KEY

1. PostgreSQL maakt geen index op de verwijzende kolom. → trage joins, en elke DELETE op de ouder scant de kindtabel

2. ON UPDATE CASCADE is bij surrogaatsleutels overbodig. Nog een argument vóór surrogaten.

Slide 20 — Gedeeltelijke uniciteit

CREATE UNIQUE INDEX deelnemer_actief_bsn_uniek
    ON deelnemer (bsn) WHERE einddatum_deelname IS NULL;

Onder actieve deelnemers is het BSN uniek; historische rijen mogen herhalen.

Kan alleen als index, niet als constraint.

Slide 23 — Opdracht 6.3

Slide 24 — Terug naar opdracht 5.6

“Welke constraint voorkomt dat twee adresperioden van dezelfde deelnemer overlappen?”

Hier is het gereedschap dat je toen miste.

Slide 25 — EXCLUDE

CREATE EXTENSION IF NOT EXISTS btree_gist;

CONSTRAINT adres_geen_overlap
    EXCLUDE USING gist (deelnemer_id WITH =, geldigheid WITH &&)

Geen twee rijen met dezelfde deelnemer én overlappende perioden.

Slide 26 — Waarom dit ertoe doet

Zonder constraint bewaakt de applicatie de overlap — en dat faalt zodra twee mutaties tegelijk binnenkomen.

Met de constraint is het onmogelijk.

Voor iedereen. Ook voor jou met psql.

Slide 29 — Gegenereerde kolommen

volledige_naam text GENERATED ALWAYS AS (
    concat_ws(' ', voorletters, tussenvoegsel, achternaam)
) STORED

De veilige vorm van denormalisatie: alleen de database schrijft hem.

Slide 30 — Domein

CREATE DOMAIN bsn_type AS text CHECK (VALUE ~ '^[0-9]{9}$');

De regel staat op één plek en geldt overal.

Enum? Ziet er netjes uit — tot je een waarde moet hernoemen. Liever een referentietabel.

Slide 37 — En nu het goede nieuws

BEGIN;
DROP TABLE deelnemer;
ROLLBACK;   -- hij is er nog

DDL is in PostgreSQL transactioneel.

Anders dan Oracle en MySQL, waar DDL automatisch vastlegt.
